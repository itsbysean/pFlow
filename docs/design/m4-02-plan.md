# M4-02 — Markdown and evidence processing

Research: local main starts at c4b6ac5. The Builder already discovers unchanged M1 envelopes and raw Markdown through shared validators. The Viewer has a safe native-DOM M1-03 renderer with literal IDs and callback-based links. SourceReference supports optional inclusive line ranges and symbols; no model change is required.

1. Reuse viewer/markdown.js in Node with an injected document from LinkeDOM. Add basic emphasis and declarative document/source link attributes to that same renderer. Serialize only nodes created by the renderer; no untrusted HTML parsing or arbitrary URL attributes. Keep raw Markdown for existing M3 indexing/highlighting. No second parser or sanitizer pipeline.
2. Add --repository-root (default --input) and the equivalent repositoryRoot Builder option. Discovery/docs remain bounded by input; source references resolve within the explicit repository root. Preserve approved Markdown evidence links to matching JSON sources.
3. Keep existing missing/unreadable files, unsafe paths, invalid ranges and stale bounds as fatal validation errors. Add a cached bounded source reader to shared validation, retaining existing defaults for M1 tests. Oversized files are explicitly unavailable with a warning and unverified line bounds, rather than read without limit.
4. Extract only explicit line ranges, preserve line text/number/indentation/UTF-8, normalize CRLF/LF/CR delimiters without adding a phantom final line, and deduplicate identical file/range content across SourceReference IDs. Retain all original location/symbol metadata in the unchanged envelope. File-level references stay location-only and warn; never guess a range.
5. Document configurable Builder-only limits: 1 MiB/source file, 200 lines/snippet, 64 KiB/snippet and 1 MiB snippet text/artifact. Skip an entire unsafe-sized snippet with a warning; never silently truncate. Invalid UTF-8 is fatal. Read each bounded referenced file once per artifact and discard its full text after processing.
6. Add rendered fragments/section metadata, snippet records and sorted processing diagnostics to private in-memory preparation state. CLI prints warnings and reports processing without writing HTML. Packaging and binding serialized controls remain M4-03 work.
7. Test rendering/serialization against malicious content, supported formatting, literal IDs, source ranges/line endings/limits/paths, separate roots and deterministic integration. Run existing Viewer/search and validation regressions, perform a separate review pass, and commit on main. Do not proceed to M4-03.

LinkeDOM is a source-tool development dependency for server-side DOM construction/serialization. It is not loaded by the offline Viewer or required to be installed in a target repository. No schema, public artifact field or execution vocabulary changes.
