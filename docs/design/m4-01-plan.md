# M4-01 — Builder foundation

Research: `main` starts at `6bd5c79`. M1-03 specifies one documentation bundle per architecture artifact: index.md and graph-linked Markdown, with repository-relative source paths. The checked-in layout uses `architecture.json` plus sibling `docs/`. The proposed `flows/` and `diagrams/` layout was not adopted. The existing Ajv/schema, semantic and Markdown-profile checks live in test support. The Viewer accepts unchanged M1 envelopes and bundle-relative raw Markdown. Node tests and offline browser tests are established.

1. Promote the existing validators into shared `validation/` modules. Keep fixture-root defaults in compatibility wrappers for existing tests. Embed the approved schema via a static JSON import so future bundling need not find the source checkout at runtime. Keep Ajv as the existing development dependency; add no packages or distribution/bundling step now.
2. Provide `node builder/cli.mjs build --input <repository-root> --output <file.html>`, help and version. The selected input is the source-reference repository root, not the nested docs directory. Discover every architecture.json through physical directories, excluding .git metadata and not traversing directory symlinks. Validate candidate file symlinks and all referenced documents/evidence against their roots. Do not inspect unrelated JSON as architecture.
3. Discover/load in stable path order, apply the existing schema/semantic/Markdown validators, and sort diagnostics by artifact, phase, location and message. Fail all preparation on any error. No execution or expression evaluation of artifact content.
4. Return an internal in-memory preparation object with input/output locations and ordered artifacts containing the unchanged architecture envelope plus exact raw Markdown records. Preserve original graph arrays/IDs and bundle-relative document paths. Do not introduce a second public schema or write this object to disk.
5. Validate the explicit output destination (HTML file, existing writable parent, no directory/symlink target or collision with loaded input/evidence). The user may explicitly choose an output outside the input tree; artifact references cannot widen the input root. Print preparation counts and an explicit no-HTML-written statement. No file or directory is created by the CLI.
6. Test arguments, help/version/exit codes, all real samples, shared validator integration, deterministic diagnostics/output/preparation, corrupt/unreadable/missing input, source/document/JSON traversal and symlinks, and output collisions. Run the full suite, review and commit on local main. Stop before HTML generation or Viewer bundling.

No M1 data fields, directory contract or execution semantics change. The source checkout needs its existing development dependencies. A future prebuilt Skill bundle must carry validation code/schema/dependencies and must not require npm install in the target repository; producing that bundle remains later work.
