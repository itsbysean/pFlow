# Preserve, stage, validate and apply

The contract has no general generated/manual section boundary. Literal entity anchors identify graph associations, not who wrote the prose. Preserve a user-maintained section by honoring its existing explicit convention. Otherwise require an approved generated merge base and use baseline → current manual edits plus baseline → new generated changes. Do not infer ownership from identical bytes alone.

The trusted merge helper uses native git merge-file on temporary text files, without target scripts or Markdown execution. Disjoint edits can merge. Conflicting edits, manual deletion, an unknown existing-file collision or deletion containing manual changes block the update. An unchanged generated candidate leaves current text byte-identical. A removed Flow's edited notes cannot be silently deleted; resolve ownership or relocate notes through an explicit reviewed proposal. Validation can also block a merge that preserves now-invalid manual graph/source references.

prepareRegeneration accepts trusted tool arguments: repositoryRoot, bundleRoot, baselineSourceRoot, baselineBundleRoot, snapshotCommit, generatedBaselineConfirmed, impactPlan, original changeSet, complete candidateGraph and candidateDocuments. These are transient working inputs, not new public metadata. generatedBaselineConfirmed is supplied only after provenance/ownership review; never set it merely to bypass a block. Current Diagram JSON must match the generated baseline semantically; reconcile manual/parallel graph edits before replacement.

The helper enforces unchanged out-of-scope Flows/evidence, planned entry rediscovery, edge identity constraints and unchanged canonical Flow sections in shared files. It preserves unrelated bundle files. It checks the original Git fingerprint, copies the bundle into private staging at its original source-relative layout, merges affected text, materializes only referenced current source blobs/contained aliases and runs the existing full schema/semantic/Markdown validator. Published citations continue to target real source paths, never staging locations. Missing source, stale ranges, dangling entry/hierarchy/async/doc references or conflicts block apply.

Review the staged diff and semantic evidence. A returned prepared object exposes stagedRoot for inspection, apply() and dispose(). Modifying stage bytes after validation invalidates its fingerprint; reprepare/revalidate instead of bypassing the check. Apply also binds current source bytes and resolved paths, including referenced ignored files. A commit-scope plan requires the current non-bundle source tree to match its selected target commit; a live working-tree guard still applies. Out-of-scope evidence cannot change behind an unchanged SourceReference object. apply rechecks source and document fingerprints and delegates only the validated bundle to the safe update helper. No target history/index operations occur.

Apply uses an owned sibling copy and two directory renames with rollback on ordinary failures. It is recoverable, not a crash-atomic multi-file commit. If restoration fails, report the retained original backupPath and stop; never delete it. Abrupt process/machine failure between renames can require recovery from that backup. Concurrent/adversarial filesystem changes are not fully eliminated by fingerprints. Bundle copies preserve bytes and permission modes, not every filesystem timestamp, inode or extended attribute. Keep unrelated/manual files and HTML byte-identical; report HTML as stale, and do not invoke the Builder. M6-03 is outside this stage.

Retain the approved new generated candidate text and its source provenance for a later run, separately from merged manual edits. The helper does not create a persistent ownership/identity store; do not treat merged current Markdown as a new generated-only base without review.

When validation/rebuild is explicitly included after regeneration, continue with [pflow-rebuild](../../pflow-rebuild/SKILL.md) on the complete current set. Standalone M6-02 still preserves HTML without rebuilding it.

Use the shared builder/bundle-layout.mjs resolver (resolveBundleRoot for a known bundle) for graphPath/docsRoot. Flat diagrams/architecture.json + root Markdown and legacy architecture.json + docs/ are supported without migration. Pass resolved baseline docsRoot to impact planning. Targeted apply requires baseline/current layout agreement and retains all Git, source separation, ownership and rollback guards; prompt incremental apply remains unsupported.
