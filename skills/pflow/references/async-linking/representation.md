# Existing graph representation

The [approved model](../contracts/model.md), [schema 1.0.0](../contracts/schema.md), [Markdown contract](../contracts/markdown.md) and [boundary representation](../external-boundaries/representation.md) remain authoritative. Use the existing M1 asynchronous sample as a representation example, not proof for a different repository.

Retain the producer's invocation node with external.kind messaging. That existing external occurrence represents the broker/system boundary; do not bypass it with a direct caller-to-handler edge or collapse all same-topic calls into a new global broker node. Preserve the local send/call and its waiting mode. An awaited send can remain sync while delivery is async.

Add a receive edge with mode async, from that messaging node to the actual registered consumer receiving node, owned by the source Flow. Usually the target is the EntryPoint's root Flow start; use another node only when inspected dispatch evidence establishes it. Do not target an EntryPoint ID (edges reference Nodes). Do not duplicate or move consumer nodes, change start nodes, replace local continuations, or add expandFlowId for message delivery. Reuse existing valid transfer edges rather than duplicating them.

The edge sourceIds must cite the publication, broker/client identity and configuration, destination construction, registration/handler binding and relevant routing/filter/group evidence. Reuse evidence records by role. Add only necessary references and opaque edge IDs, retaining identities for established unchanged relationships. The edge label can state a source-backed route, eligibility condition or competing group. Labels describe possibilities, not forced sequencing or delivery guarantees. Concise diagnostics explain unresolved candidates outside the public JSON schema. Identify a candidate with the existing publication Node ID and consumer EntryPoint/receiving Node ID; no new candidate identity model is needed. For an unregistered declaration without an entry identity, cite its source location/symbol rather than assigning confirmed graph IDs. Generic external.attributes can retain established metadata; do not add new model fields, enum values or nested value objects.

Multiple eligible consumer groups can have separate receive edges; competing members can each have a possibility edge with a label that identifies the competition. Those edges are alternatives within that group, not a claim every member receives a copy. Retain independent producers/destinations and branch guards; do not merge contexts with different broker bindings. If an adapter's dispatch contract is unknown, report the gap instead of assuming fanout or competition.

Cycles are valid references between existing Flows. Inspect a finite set of contexts/pairs, not every runtime delivery. The validator permits cycles and enforces source ownership, referenced nodes and async cross-flow receive. It does not prove broker or routing compatibility. The existing Viewer can show a remote target as a boundary stub; this stage does not add navigation behavior or copy its consumer graph into the producer diagram.

Preserve existing canonical document links and source citations. When relocating a bundle, rebase Markdown evidence definitions to the same repository files and exact ranges; JSON source paths stay repository-relative. If evidence associations change, keep existing documents valid. Use concise analysis notes for new link diagnostics; do not generate final execution documentation in this stage. Test fixture Markdown is contract/evidence scaffolding, not an implementation of M5-05.
