# Reanalysis and candidate content

Use one working copy of the existing graph and evidence ledger. Reanalyze only approved affected scopes and necessary binding, configuration, registration and transfer context. A source change can remove a relationship; complete replacements for affected Flow content must not retain old edges by union. Source evidence and current reachability decide the new graph, not the desire to minimize a diff.

Retain IDs for unchanged logical entries, contexts, invocation occurrences, relationships and evidence roles. A move can keep an ID only when inspected declarations/bindings establish continuity. Git similarity alone is insufficient. Unknown identity uses a fresh opaque ID; do not donate a removed ID to an unrelated replacement. An edge with changed endpoints, kind or transfer mode needs a fresh relationship identity. Other semantic changes still need source review; the helper is not an identity matcher.

Keep flow-owned nodes/edges, canonical starts, reusable expandFlowId navigation and evidence-backed receive/async links. Revalidate both ends of changed async routing and remove incompatible recipients. Preserve the broker boundary and local waiting semantics. New registrations update entry roots and index links; removed activation removes entry/index links, but shared detail survives if other contexts still use it. Do not copy consumer graphs or invent unresolved targets.

Refresh every retained SourceReference in changed source files, including unchanged text whose path/range shifted. Preserve a source ID only for the same evidence role. Update exact Markdown definitions/citations together. Package/import, active loader, selected configuration, invocation and registration evidence must still prove claims. Shared evidence can widen the affected scope. Remove unused obsolete references only after checking surviving/manual citations; unresolved manual associations block deletion.

Generate concise canonical Markdown using the M5 rules. Avoid wording changes when behavior is unchanged. Prefer omitted replacements for unchanged documents. If several Flow sections share a document, preserve unaffected sections exactly; only refresh necessary shared definitions with the affected source associations. Nodes/edges remain nested under their owning/source Flow and retain exact-ID docs backlinks.

The supplied candidate graph is the complete envelope after reviewed replacements; it is not a second patch schema. Candidate documents map existing bundle-relative docs paths to proposed generated text (or null for a proven obsolete generated file) only as temporary helper arguments. Generate this text from the trusted generated base, leaving current manual edits for preservation; do not accidentally reapply manual edits into both merge sides. Unknown files/collisions are not generated-owned. No HTML build is part of candidate generation.
