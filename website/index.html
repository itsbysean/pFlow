An AI agent Skill for process documentation 프로세스 문서를 만드는 AI 에이전트 스킬

Understand how systems and teams work. 시스템과 팀의 업무 흐름을 이해하세요.

pFlow turns code evidence or a process you describe in natural language into clear documentation and an interactive HTML Viewer. pFlow는 코드 근거나 자연어로 설명한 프로세스를 읽기 쉬운 문서와 인터랙티브 HTML Viewer로 만듭니다.

What pFlow doespFlow가 하는 일

See the flow. Read the evidence. 흐름을 보고, 근거를 확인하세요.

Use repository analysis for software systems. Use a natural-language description for any other process. 소프트웨어 시스템은 저장소를 분석하고, 그 밖의 프로세스는 자연어로 설명해 도식화할 수 있습니다.

01

Explore code architecture코드 아키텍처 탐색

Follow confirmed entry points, internal calls, decisions, external boundaries, and asynchronous links.확인된 진입점, 내부 호출, 분기, 외부 경계와 비동기 연결을 따라갑니다.

02

Map any described process설명한 프로세스 도식화

Describe business, service, team, or everyday steps. pFlow uses the facts you provide and asks about important gaps.비즈니스, 서비스, 팀, 일상 프로세스를 설명하세요. pFlow는 제공한 사실을 사용하고 중요한 정보가 빠지면 질문합니다.

03

Navigate interactive flows인터랙티브 흐름 탐색

Select nodes, follow branches, and open reusable detail flows in the generated Viewer.생성된 Viewer에서 노드를 선택하고, 분기를 살펴보고, 연결된 상세 흐름을 엽니다.

04

Link diagrams and documents다이어그램과 문서 연결

Move between a diagram selection and its related Markdown section. Search the included documentation.다이어그램에서 연결된 Markdown 문서로, 문서에서 관련 항목으로 이동하고 포함된 문서를 검색합니다.

05

Keep references visible근거 참조 확인

Review source snippets for repository analysis and captured statements for prompt-based processes when available.가능한 경우 저장소 분석은 소스 발췌를, 프롬프트 기반 프로세스는 기록된 설명을 근거로 확인합니다.

06

Share a standalone Viewer독립 실행형 Viewer 공유

Open the single HTML output in a browser. It includes its Viewer assets and does not need a server.단일 HTML 결과물을 브라우저에서 여세요. Viewer 리소스가 포함되어 서버가 필요하지 않습니다.

How to use pFlowpFlow 사용 방법

Start with a Skill. Ask in plain language.Skill을 설치하고 자연어로 요청하세요.

No pFlow command is needed to invoke the Skill. Ask your Skills-enabled coding agent for the work you want.Skill을 실행하는 pFlow 전용 명령은 없습니다. Skills를 지원하는 코딩 에이전트에게 필요한 작업을 자연어로 요청하세요.

  1. 01

    Install the Skill folderSkill 폴더 설치

    Copy the repository's skill/ folder into the Skills directory supported by your agent. Name the installed folder pflow. Keep SKILL.md, references/, and scripts/pflow.mjs together.저장소의 skill/ 폴더를 사용하는 에이전트가 지원하는 Skills 디렉터리에 복사하세요. 설치 폴더 이름은 pflow로 둡니다. SKILL.md, references/, scripts/pflow.mjs를 함께 유지하세요.

    The directory path depends on your agent. Use that agent's documented Skills location.디렉터리 경로는 에이전트마다 다릅니다. 해당 에이전트 문서에서 Skills 위치를 확인하세요.

  2. 02

    Check the runtime런타임 확인

    pFlow requires Node.js 24 or newer. It does not need an npm install or a web server at runtime.pFlow에는 Node.js 24 이상이 필요합니다. 실행할 때 npm 설치나 웹 서버는 필요하지 않습니다.

    node /path/to/pflow/scripts/pflow.mjs --help

    Replace the path with the installed Skill location. This checks the packaged CLI; the agent invokes the Skill through its own Skills workflow.설치한 Skill 경로로 바꾸세요. 이 명령은 패키지 CLI를 확인하며, 에이전트는 자체 Skills 방식으로 Skill을 실행합니다.

  3. 03

    Choose the input mode입력 방식을 선택

    For a codebase, name the repository root and the entry point or area to trace. For another process, describe its steps, conditions, and outcomes directly.코드 저장소는 루트 경로와 추적할 진입점 또는 영역을 지정하세요. 다른 프로세스는 단계, 조건, 결과를 직접 설명하세요.

  4. 04

    Answer material questions중요한 질문에 답변

    pFlow asks when a missing start, order, branch, or outcome changes the diagram. It does not fill gaps with assumed rules.시작점, 순서, 분기, 결과의 누락이 도식에 영향을 주면 pFlow가 질문합니다. 확인되지 않은 규칙을 임의로 채우지 않습니다.

  5. 05

    Review the generated files생성된 파일 검토

    Review the Markdown and graph JSON as agent-readable context. Check that cited evidence supports each relationship.에이전트가 읽는 Markdown과 그래프 JSON을 검토하세요. 인용된 근거가 각 관계를 뒷받침하는지 확인하세요.

  6. 06

    Open and explore the HTMLHTML 열고 탐색

    Open the reported architecture.html in a browser. Select a flow or node, follow linked docs, search, and switch the Viewer theme.에이전트가 안내한 architecture.html을 브라우저에서 여세요. Flow나 노드를 선택하고, 연결 문서와 검색을 이용하고, Viewer 테마를 바꿔 보세요.

Updating existing docs기존 문서 업데이트

For repository-based docs, ask pFlow to update the changed scope. It can use its impact, regeneration, and rebuild workflows with review checks. Prompt-based process docs support full generation only; if existing content has unclear ownership, pFlow asks before replacing it.저장소 기반 문서는 변경된 범위를 pFlow에 업데이트해 달라고 요청하세요. 영향 분석, 재생성, 재빌드 흐름을 검토 단계와 함께 사용할 수 있습니다. 프롬프트 기반 프로세스 문서는 전체 생성만 지원하며, 기존 내용의 소유 범위가 불분명하면 교체 전에 확인합니다.
